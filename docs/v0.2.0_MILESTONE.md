# v0.2.0 milestone plan

**Goal:** `make reproduce` works end-to-end from a fresh clone of the
main branch — no manual copy-paste, no missing files, no CLI errors.

**Stretch goal:** trained checkpoints are pullable from Zenodo via
`python -m detect.registry.download`, so a user can skip training and
go straight to evaluation.

**Branch:** `feat/v0.2.0-cli-reproduce`

## Scope decision

v0.2.0 has two possible sizes. We're committing to the **smaller (A)**
first and treating (B) as a stretch that ships in v0.2.1 if we run out
of time.

**(A) Reproduction-only (this milestone):**
- `synth.cli` — thin CLI wrapping the existing generator wrappers
- `synth.validate` — schema-conformance checker for a cohort directory
- `detect.cli` — thin CLI wrapping training + evaluation + feature
  extraction
- `configs/synth/demo_cohort.yaml` — 3-run, 2-day, 10-trader
  toy config designed to run in ~1 minute on CPU
- Verified `make reproduce` runs green

**(B) Checkpoints (stretch):**
- SHA-256 + metrics manifest for v1, v3, v4, tier-2 checkpoints
- Upload checkpoints to Zenodo as a separate deposit
- Write `detect.registry.download` helper that pulls + verifies
- README changes to describe the new `make checkpoints` flow

## Sequencing (safest first)

Each step is small, pauseable, and testable. The safest ordering:

### Step 1 — write `configs/synth/demo_cohort.yaml` [~15 min, ZERO risk]

Pure spec file. No code changes. Codifies what "demo cohort" means so
the CLI has something to consume in Step 3. Even if we abandon the
milestone, this file is useful documentation.

### Step 2 — write `synth/src/synth/validate/__init__.py` [~1 hour, LOW risk]

Reads a cohort directory, checks each of the 10 files against
[SCHEMA.md](../SCHEMA.md), returns a report. Doesn't invoke synth
itself. Standalone — testable against any cohort dir (real or fake).

### Step 3 — write `synth/src/synth/cli.py` [~1 hour, MEDIUM risk]

`argparse` or `click`-based CLI with two subcommands:
- `generate --config <yaml> --out <dir>` — dispatches to the right
  existing wrapper based on config
- `validate <dir>` — thin wrapper around `synth.validate`

Risk = the existing wrappers have their own arg conventions and side
effects. Iteration expected.

### Step 4 — write `detect/src/detect/cli.py` [~1.5 hours, MEDIUM risk]

Three subcommands:
- `features --cohort <dir>` — extracts 6 engineered features to disk
- `train --cohort <dir> --model {tier2,v1,v4}` — trains the requested
  model, saves to `<dir>/detect_<model>/`
- `evaluate --cohort <dir> --model {tier2,v1,v4}` — loads trained
  model, produces per-run AUC + summary

Risk = the training scripts under `training/` have module-level import
side effects and cohort-path assumptions from the pre-monorepo layout.
Some plumbing will need rewiring.

### Step 5 — end-to-end verification [~1 hour, unknown risk]

```bash
# Fresh venv
python -m venv .venv-v020-verify
source .venv-v020-verify/bin/activate
pip install -e ./synth -e ./detect
make reproduce
# Should complete in ~2 min. Check `cohorts/demo/*/detect_tier2/` exists and non-empty.
```

If this passes → merge to main + tag v0.2.0 + Zenodo picks it up → done.

### Step 6 — optional stretch: checkpoints (only if Steps 1–5 land clean)

Separate PR, separate Zenodo deposit for the checkpoint bundle.

## Guardrails

- **No changes to main.** Everything on `feat/v0.2.0-cli-reproduce`
  until Step 5 passes cleanly.
- **Each step is its own commit.** Small, reviewable, revertable.
- **If a step balloons past 2× its estimate, we stop and reassess** —
  the alternative is another Phase 3.5 patch-cascade situation.
- **When in doubt, wrap don't rewrite.** The existing wrappers work;
  a CLI that shells out to them is fine even if aesthetically it
  would be cleaner to refactor.

## Deferred to later

Explicitly not in v0.2.0 scope (to keep the milestone shippable):

- HuggingFace Hub mirror for v4 checkpoint
- Full GPU-training reproduction of the paper cohorts
- Fixture-migration to bring the `_legacy/` tests back online
- Docker-based `make reproduce` variant

These get their own milestones once v0.2.0 is out.
